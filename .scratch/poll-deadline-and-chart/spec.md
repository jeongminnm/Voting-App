# Spec: 투표 마감 시각 + 결과 그래프 (부록 기능 추가)

Status: ready-for-agent

## Problem Statement

동아리 회장의 요청: "투표를 계속 열어두니까 사람들이 마감 없이 늘어져서 참여를 안 해요. 마감 시간을 정할 수 있게 해주시고, 결과도 숫자 말고 그래프로 보고 싶어요."

지금은 투표(Poll)에 끝이 없어 참여를 미루게 되고, 결과 화면은 선택지별 득표수 숫자 리스트뿐이라 한눈에 비교하기 어렵다. (과제 요구사항 1: 투표 마감 시간 설정, 2: 투표 결과를 그래프로 표시)

## Solution

- 투표를 만들 때 **마감 시각**을 선택적으로 정할 수 있다. 정하지 않으면 지금처럼 마감 없이 계속 진행된다.
- 마감 시각은 항상 한국 시간(KST)으로 입력받고 보여준다 (ADR-0002).
- 투표 화면과 결과 화면에 마감 시각과 마감 여부가 보인다. 마감이 지나면 투표 화면의 투표 폼이 비활성화되고, 서버도 투표를 거부한다.
- 결과 화면의 숫자 리스트를 선택지별 가로 막대그래프(득표수와 퍼센트)와 총 투표수로 바꾼다.

## User Stories

### 마감 시각 정하기 (`/new`)

1. As a 투표를 만드는 사람, I want 투표를 만들 때 "마감 시간"을 선택적으로 입력하기를, so that 참여 기한을 정할 수 있다
2. As a 투표를 만드는 사람, I want 마감 시간을 비워 두면 마감 없는 투표가 되기를, so that 기한이 필요 없는 투표는 지금처럼 만들 수 있다
3. As a 투표를 만드는 사람, I want 날짜와 시간을 브라우저의 날짜·시간 입력으로 고르기를, so that 형식을 외우지 않아도 된다
4. As a 투표를 만드는 사람, I want 입력한 시각이 항상 한국 시간으로 해석되기를, so that 내 기기 시간대 설정과 상관없이 의도한 시각에 마감된다
5. As a 투표를 만드는 사람, I want 지금이거나 이미 지난 시각을 넣으면 화면에서 먼저 안내받기를, so that 만들자마자 마감된 투표를 실수로 만들지 않는다
6. As a 투표를 만드는 사람, I want 화면 검증을 우회해도 서버가 지난 시각을 거부하기를, so that 잘못된 마감 시각이 저장되지 않는다

### 마감 시각 보기 / 마감된 투표 (`/polls/[id]`)

7. As a 투표자, I want 마감 전 투표 화면에서 `마감: YYYY-MM-DD HH:mm (KST)` 를 보기를, so that 언제까지 투표해야 하는지 안다
8. As a 투표자, I want 마감이 없는 투표에서는 마감 표시가 보이지 않기를, so that 불필요한 정보에 헷갈리지 않는다
9. As a 투표자, I want 마감된 투표 화면에서도 질문과 선택지를 보기를, so that 어떤 투표였는지 알 수 있다
10. As a 투표자, I want 마감된 투표에서는 선택지와 "투표하기" 버튼이 비활성화되고 "마감된 투표입니다" 가 보이기를, so that 더 이상 투표할 수 없음을 바로 안다
11. As a 투표자, I want 마감된 투표 화면에서도 "결과 보기" 링크를 쓰기를, so that 최종 결과를 확인할 수 있다
12. As a 투표자, I want 화면을 열어 둔 채 마감 시각이 지난 뒤 제출하면 "마감된 투표입니다." 안내를 보기를, so that 왜 투표가 반영되지 않았는지 안다
13. As a 투표자, I want 마감 시각 이후의 투표 요청은 서버가 거부하기를, so that 마감 뒤에 결과가 바뀌지 않는다
14. As a 투표자, I want 마감 시각이 없는 기존 투표는 지금처럼 투표할 수 있기를, so that 기능 추가 전에 만든 투표도 문제없이 쓴다

### 결과 그래프 (`/polls/[id]/results`)

15. As a 투표자, I want 결과를 선택지별 가로 막대그래프로 보기를, so that 어느 선택지가 많이 받았는지 한눈에 비교한다
16. As a 투표자, I want 막대마다 선택지 이름과 `N표 (xx%)` 가 함께 보이기를, so that 정확한 수치도 알 수 있다
17. As a 투표자, I want 그래프 위에 `총 N표` 가 보이기를, so that 전체 참여 규모를 안다
18. As a 투표자, I want 퍼센트가 정수로 반올림되어 보이기를, so that 읽기 쉽다
19. As a 투표자, I want 막대 길이가 실제 비율과 정확히 맞기를, so that 반올림 때문에 그래프가 왜곡되지 않는다
20. As a 투표자, I want 득표수가 많은 선택지가 위에 오고 동률이면 이름순으로 정렬되기를, so that 순위를 바로 알고 새로고침해도 순서가 흔들리지 않는다
21. As a 투표자, I want 아직 아무도 투표하지 않았을 때도 모든 선택지가 빈 막대와 `0표 (0%)` 로 보이고 `총 0표` 와 "아직 아무도 투표하지 않았습니다." 가 보이기를, so that 오류 없이 현재 상태를 안다
22. As a 투표자, I want 결과 화면에서도 마감 시각과 마감 여부를 보기를, so that 진행 중 결과인지 최종 결과인지 구분한다
23. As a 투표자, I want 결과 화면이 지금처럼 항상 최신 득표수를 보여주기를, so that 방금 한 투표가 그래프에 반영된다
24. As a 투표자, I want 모든 막대가 기존 화면과 같은 색 체계(다크 모드 포함)로 보이기를, so that 화면이 일관된다

### API 사용자

25. As an API 사용자, I want `POST /api/polls` 에 `closesAt` (시간대가 포함된 ISO 8601 문자열, `null`, 또는 생략)을 보내기를, so that 마감 시각을 모호하지 않게 전달한다
26. As an API 사용자, I want 시간대가 없거나 형식이 잘못된 `closesAt`, 또는 지금 이전인 `closesAt` 이 `400` 과 `{ error }` 로 거부되기를, so that 잘못된 값이 저장되지 않는다
27. As an API 사용자, I want `GET /api/polls/[id]` 응답에 `closes_at` (ISO 문자열 또는 `null`)이 포함되기를, so that 마감 시각을 알 수 있다
28. As an API 사용자, I want 마감된 투표에 대한 `POST /api/polls/[id]/vote` 가 `409` 와 `{ error: "마감된 투표입니다." }` 를 돌려주기를, so that 입력 오류(400)·없는 투표(404)와 구분한다

## Implementation Decisions

### 기존 결정과의 관계

- 기본 앱 스펙(`.scratch/voting-app-mvp/spec.md`)의 "추가 테이블이나 컬럼은 만들지 않는다"와 "Out of Scope: 투표 마감 시간, 결과 그래프, 총 투표수·퍼센트"는 기본 앱 당시의 결정이다. **이 스펙이 그 결정을 바꾼다**: `polls.closes_at` 컬럼 하나를 추가하고, 결과 화면을 그래프와 총 투표수·퍼센트로 바꾼다. 그 밖의 기본 앱 결정(익명·중복 투표 방지 없음(ADR-0001), 선택지 2~5개, 입력 검증 규칙, 오류 형식, 읽기/쓰기 경로, 테스트 원칙)은 그대로 유지한다.
- 선택지 **조회 순서**는 기본 앱 결정대로 보장하지 않는다(SQL 에 `order by` 없음, 순서 컬럼 없음). 투표 화면은 DB 가 돌려주는 순서를 그대로 쓴다. 정렬은 **결과 화면 표시에서만** 한다.

### 스키마

- `polls` 에 `closes_at timestamptz` (nullable, 기본값 없음)를 추가한다. `null` 이면 마감 없음이다. 기존 투표는 모두 `null` 이 되어 마감 없이 동작한다.
- 마이그레이션 SQL: `alter table polls add column closes_at timestamptz;` 를 스키마 SQL 파일에 추가하고, 수업자료대로 사람이 Neon SQL Editor 에서 직접 실행한다. 구현 에이전트는 SQL 을 실행하지 않고 사용자에게 요청한다.

### 마감 판정

- **마감됨** = `closes_at` 이 있고 `현재 시각 >= closes_at`. 마감 시각 정각부터 마감이다. 판정은 서버의 현재 시각으로 한다.
- 화면을 열어 둔 채 마감 시각이 지나도 자동으로 바뀌지 않는다(카운트다운·폴링 없음). 새로고침하면 마감 상태로 보이고, 그 전에 제출하면 서버가 `409` 로 거부한다.

### 시간대 (ADR-0002)

- 마감 시각은 항상 KST(Asia/Seoul, `+09:00`)로 해석하고 표시한다. DB 에는 절대 시각으로 저장한다.
- **KST 변환·표시 모듈** (순수 함수, 서버·화면 공용):
  - `datetime-local` 값(`YYYY-MM-DDTHH:mm`) → KST ISO 문자열(`YYYY-MM-DDTHH:mm:00+09:00`). 예: `2026-09-30T18:00` → `2026-09-30T18:00:00+09:00`.
  - 절대 시각 → 표시 문자열 `YYYY-MM-DD HH:mm (KST)`. 예: `2026-09-30T09:00:00Z` → `2026-09-30 18:00 (KST)`, `2026-09-30T15:00:00Z` → `2026-10-01 00:00 (KST)`.
  - 실행 환경(서버·브라우저)의 시간대와 상관없이 같은 결과를 내야 한다.

### 입력 검증 (기존 투표 입력 검증 모듈에 추가)

- `closesAt` 이 생략되거나 `null` 이면 마감 없음.
- `closesAt` 이 있으면: 문자열이어야 하고, 시간대(`Z` 또는 `±HH:MM`)가 포함된 ISO 8601 형식이어야 한다. 아니면 거부.
- 현재 시각과 같거나 이전이면 "마감 시각은 지금 이후로 입력해 주세요." 로 거부. 서버는 요청을 받은 시점의 서버 시각으로 최종 판단한다.
- 화면과 서버가 같은 검증 함수를 쓴다(기존 원칙). 검증 결과 값에 마감 시각(없으면 `null`)을 포함해 투표 생성에 넘긴다.

### polls 데이터 접근 모듈

- 투표 상세 조회가 `closes_at` 을 함께 돌려준다 (ISO 문자열 또는 `null`).
- 투표 생성이 마감 시각(또는 `null`)을 함께 저장한다. 투표와 선택지를 한 문장으로 저장하는 기존 방식은 유지한다.
- 득표 1 증가는 기존 인터페이스를 유지한다. 마감 여부 판단은 Route Handler 가 상세 조회 결과로 한다.

### 결과 계산 모듈 (순수 함수)

- 입력: 선택지 목록(`id`, `label`, `vote_count`). 출력: 총 투표수와, 선택지별 `label`, `vote_count`, 표시용 정수 퍼센트, 막대용 정확한 비율.
- 퍼센트 = `Math.round(vote_count / 총 투표수 × 100)`. 합계 보정 없음(99%·101% 허용). 예: 1/3 → 33, 2/3 → 67, 1/8 → 13.
- 막대 비율 = 반올림 전 정확한 값 (`vote_count / 총 투표수`).
- 총 투표수가 0 이면 모든 퍼센트와 비율은 0.
- 정렬: 득표수 내림차순, 동률이면 선택지 이름 오름차순(한국어 기준 문자열 비교, `localeCompare(…, "ko")`).

### API 계약 변경

- `POST /api/polls`
  - 요청: `{ question: string, options: string[], closesAt?: string | null }`
  - `closesAt` 형식 오류·시간대 없음·지금 이전: `400`, `{ error }`
  - 나머지는 기존과 같다 (`201`, `{ id }`).
- `GET /api/polls/[id]`
  - 성공: `200`, `{ id, question, created_at, closes_at, options: [{ id, label, vote_count }] }`. `closes_at` 은 ISO 문자열 또는 `null`.
- `POST /api/polls/[id]/vote`
  - 마감 시각이 지난 투표: `409`, `{ error: "마감된 투표입니다." }`, 득표수 변경 없음.
  - 확인 순서: 없는 투표(`404`) → 마감(`409`) → 선택지 확인(`400`). 나머지는 기존과 같다.
- 요청 필드는 기존처럼 camelCase(`closesAt`), 응답 필드는 DB 컬럼 이름(`closes_at`)을 쓴다. 모든 오류는 기존대로 `{ error: "<한국어 안내 문구>" }`.

### 화면

- **`/new`**: 선택 입력 "마감 시간" (`datetime-local`). 비우면 마감 없음. 제출 시 KST ISO 문자열로 바꿔 `closesAt` 으로 보낸다. 지난 시각은 화면에서 먼저 안내한다.
- **`/polls/[id]`**:
  - 마감 전이고 마감 시각이 있으면 `마감: YYYY-MM-DD HH:mm (KST)`.
  - 마감 후에는 "마감된 투표입니다" 를 표시하고, 선택지(라디오 버튼)와 "투표하기" 버튼을 보여주되 비활성화한다.
  - 마감 시각이 없으면 마감 표시 없음.
  - "결과 보기" 링크는 항상 유지. 제출이 `409` 로 거부되면 응답 문구를 그대로 보여준다.
- **`/polls/[id]/results`**:
  - 그래프 위에 `총 N표`. 선택지마다 이름, 가로 막대, `N표 (xx%)`.
  - 마감 시각이 있으면 마감 전에는 `마감: YYYY-MM-DD HH:mm (KST)`, 마감 후에는 "마감된 투표입니다" 와 마감 시각을 함께 표시.
  - 0건이면 `총 0표`, "아직 아무도 투표하지 않았습니다.", 모든 선택지 빈 막대와 `0표 (0%)`.
  - 결과 화면은 서버 컴포넌트로 유지하고, 요청마다 최신 값을 보여준다.
- **`ResultBar` 컴포넌트**: 계산된 결과 한 줄(이름, 득표수, 퍼센트, 비율)을 받아 그리기만 한다. 회색 배경 막대 안을 정확한 비율만큼 채운다. 채움 색은 기존 버튼과 같은 전경색, 모든 막대 같은 색. 차트 라이브러리는 쓰지 않는다.
- **목록 `/`**: 변경 없음 (질문만 최신순).

## Testing Decisions

- **좋은 테스트의 기준**: 기존과 같다. 외부에서 관찰 가능한 동작(HTTP 상태 코드·JSON 본문·득표수 변화, 순수 함수의 입력→출력)만 검증하고 SQL 이나 내부 구현을 검증하지 않는다.
- **테스트 경계는 2개**:
  1. **Route Handler 3개** (기존 경계). polls 데이터 접근 모듈은 기존대로 메모리 기반 가짜로 대체하고, 가짜에 `closes_at` 을 추가한다. 현재 시각은 Vitest 가짜 시계(`vi.setSystemTime`)로 고정한다.
  2. **순수 함수** (이번에 추가): 결과 계산 모듈, KST 변환·표시 모듈.
- **테스트할 것**:
  - `POST /api/polls`: `closesAt` 이 미래 KST ISO → `201` 이고 `GET` 의 `closes_at` 이 같은 절대 시각; 생략·`null` → `closes_at` 이 `null`; 시간대 없음·형식 오류·문자열 아님 → `400`; 지금과 같음·과거 → `400`.
  - `POST /api/polls/[id]/vote`: 마감 전 투표 정상; 마감 없는 투표 정상; 마감 시각 정각과 이후 → `409` + `{ error: "마감된 투표입니다." }`, 득표수 변화 없음; 없는 투표는 마감보다 먼저 `404`.
  - 결과 계산: 0건(총 0, 모두 0%·비율 0), 1건(100%), 동률, 1/3 → 33, 2/3 → 67, 1/8 → 13, 막대 비율은 반올림 전 값, 득표순 정렬, 동률 시 이름순 정렬.
  - KST 변환·표시: `2026-09-30T18:00` → `2026-09-30T18:00:00+09:00`; `2026-09-30T09:00:00Z` → `2026-09-30 18:00 (KST)`; `2026-09-30T15:00:00Z` → `2026-10-01 00:00 (KST)`.
- **자동 테스트하지 않는 것**: 실제 SQL(마이그레이션 포함), UI 렌더링(`ResultBar`, 비활성화 폼, 마감 표시, `datetime-local` 입력) — `npm run dev` 로 직접 확인. 컴포넌트 테스트, Testing Library, jsdom, E2E 는 추가하지 않는다.
- **기존 테스트(prior art)**: `app/api/polls/**/route.test.ts` 의 Route Handler 테스트와 `test/fake-polls.ts` 가짜 모듈. 기존 37개 테스트는 계속 통과해야 한다.

## Out of Scope

- 마감 시각 수정, 마감 후 다시 열기, 수동 마감 버튼.
- 목록 화면의 마감 표시(배지·마감 시각).
- 카운트다운, 자동 새로고침·폴링, 마감 알림.
- 사용자별 시간대 지원 (ADR-0002).
- 선택지별 다른 색, 1위 강조, 원그래프, 차트 라이브러리.
- 투표 화면의 선택지 정렬 (DB 순서 유지).
- 기본 앱 스펙에서 범위 밖으로 둔 기능 중 중복 투표 방지, 복수 선택, 투표 삭제 등은 계속 범위 밖이다. Admin 로그인·세션·`proxy.ts` 가드는 `.scratch/admin-login/spec.md`에서 별도로 관리하며, 이 스펙의 마감 시간과 결과 그래프 요구사항은 변경하지 않는다.
