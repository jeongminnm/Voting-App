# 01: 투표 만들기

**What to build:** 누구나 `/new` 에서 질문 하나와 선택지(Option) 2~5개로 투표(Poll)를 만들 수 있다. 만든 투표는 `/` 목록에 최신순으로 나타나고, 만든 직후 `/polls/[id]` 로 이동해 그 투표의 질문과 선택지를 (아직 투표 기능 없이) 확인한다. 모든 페이지 상단에는 `투표 앱 · 제작자: 임정민` Header 가 보인다. 이 티켓은 이후 티켓이 쓰는 기반(스키마, DB 연결, polls 데이터 접근 모듈, 입력 검증, Vitest)도 함께 만든다.

스펙: `.scratch/voting-app-mvp/spec.md` (User Stories 1–23, 31, 38–39, 41–42)

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

### 기반

- [x] 수업자료 2장 스키마(`polls`, `options`, uuid 기본키, `on delete cascade`, `vote_count` 기본값 0)를 SQL 파일로 저장소에 남긴다. 추가 테이블·컬럼은 없다.
- [x] 구현 에이전트는 SQL 파일을 만든 뒤 사용자에게 Neon SQL Editor 에서 직접 실행해 달라고 요청하고, 실행 확인 후 DB 가 필요한 수동 확인을 진행한다.
- [x] DB 연결은 환경변수 `DATABASE_URL` 로만 `@neondatabase/serverless` 클라이언트를 만든다 (ORM 없음, raw SQL).
- [x] polls 데이터 접근 모듈이 투표 목록 조회(최신순), 투표 상세 조회(선택지·득표수 포함, 없으면 "없음"), 투표 생성(새 id 반환)을 제공한다. 투표 관련 SQL 은 모두 이 모듈에 있다.
- [x] 서버·화면 공용 입력 검증 함수가 앞뒤 공백을 정리한 값 또는 한국어 오류 문구를 돌려준다: 빈 질문, 질문 200자 초과, 선택지 2개 미만·5개 초과, 빈 선택지, 선택지 100자 초과, 같은 투표 안의 중복 선택지 이름을 거부한다.
- [x] uuid 형식이 아닌 id 는 DB 조회 없이 "없음"으로 처리한다.
- [x] Vitest 를 설치·설정하고 `npm run test` 로 실행된다.

### API

- [x] `POST /api/polls` 가 `{ question, options: string[] }` 를 받아 성공 시 `201` 과 `{ id }` 를 돌려준다. 공백이 정리된 값이 저장되고 모든 선택지의 득표수는 0 이다.
- [x] 검증 실패와 잘못된 JSON 은 `400` 과 `{ error: "<한국어 안내 문구>" }` 이다.
- [x] `GET /api/polls/[id]` 가 `200` 과 `{ id, question, created_at, options: [{ id, label, vote_count }] }` 를 돌려준다.
- [x] 없는 투표·형식이 잘못된 id 는 `404` 와 `{ error }` 이다.

### 화면

- [x] 루트 레이아웃의 공통 Header 에 `투표 앱 · 제작자: 임정민` 이 모든 페이지 상단에 보이고, "투표 앱"은 `/` 링크다.
- [x] `/` 는 서버 컴포넌트가 polls 데이터 접근 모듈로 직접 읽어 질문만 최신순으로 나열하며, 각 항목은 `/polls/[id]` 링크다. 상단에 항상 "투표 만들기" 링크가 있다.
- [x] 투표가 없으면 `/` 에 "아직 투표가 없습니다" 안내와 "투표 만들기" 링크가 보인다.
- [x] `/new` 는 질문 입력 1개와 선택지 입력 2개로 시작한다. "선택지 추가"로 최대 5개까지 늘릴 수 있고, 5개가 되면 더 추가할 수 없다. 3번째 선택지부터 삭제 버튼이 있고 1·2번째는 삭제할 수 없다.
- [x] `/new` 는 제출 전에 공용 검증 함수로 화면 검증을 하고 오류 문구를 보여준다. 통과하면 `POST /api/polls` 를 `fetch` 로 호출하고, 서버 오류 시 응답의 `error` 문구를 그대로 보여준다.
- [x] 생성 성공 시 `/polls/[id]` 로 이동한다.
- [x] `/polls/[id]` 는 서버 컴포넌트가 직접 읽어 질문과 선택지를 보여준다 (투표 폼은 02 에서 추가). 없는 투표·형식이 잘못된 id 는 `notFound()` 로 404 화면이다.
- [x] 모든 화면 문구는 한국어이고, 스타일은 Tailwind 로 간단하고 깔끔하게.

### 테스트 (Route Handler 경계, polls 데이터 접근 모듈은 메모리 가짜)

- [x] `POST /api/polls` 정상 생성 → `201`, `{ id }`, 이후 `GET /api/polls/[id]` 로 공백이 정리된 질문·선택지와 득표수 0 이 조회된다.
- [x] 경계값 허용: 선택지 2개·5개, 질문 200자, 선택지 100자.
- [x] 거부(`400` + `{ error }`): 빈/공백 질문, 선택지 1개·6개, 빈/공백 선택지, 중복 선택지 이름, 질문 201자, 선택지 101자, 잘못된 JSON.
- [x] `GET /api/polls/[id]`: 없는 id·형식이 잘못된 id → `404` + `{ error }`.
- [x] 테스트는 상태 코드와 JSON 본문 같은 외부 동작만 검증하고 SQL 문자열을 검증하지 않는다. `npm run test` 가 모두 통과한다.

### 수동 확인 (`npm run dev`)

- [x] 스키마 실행 후 `/new` 에서 투표를 만들면 `/polls/[id]` 로 이동하고, `/` 목록 맨 위에 보인다.
- [x] 선택지 추가·삭제 제한과 화면 검증 문구가 동작한다.
- [x] 모든 페이지에 Header 가 보인다.
