# 02: 투표하기

**What to build:** 투표자(Voter)가 `/polls/[id]` 에서 라디오 버튼으로 선택지(Option) 하나를 골라 제출하면(투표 행위, Vote), 그 선택지의 득표수만 1 오르고 결과 화면(`/polls/[id]/results`)으로 이동한다. 선택하지 않고 제출하면 화면에서 막힌다. 다른 투표의 선택지나 잘못된 요청은 서버가 거부하고 득표수는 바뀌지 않는다. 로그인이나 중복 투표 방지는 없다 (ADR-0001).

스펙: `.scratch/voting-app-mvp/spec.md` (User Stories 24–28, 30, 32, 40–42)

**Blocked by:** 01 (투표 만들기)

**Status:** ready-for-agent

### 데이터

- [x] polls 데이터 접근 모듈에 득표 1 증가 기능을 추가한다: 투표 id 와 선택지 id 를 받아 **그 투표에 속한 선택지일 때만** `vote_count = vote_count + 1` 로 원자적으로 증가시키고 성공 여부를 돌려준다. 동시 투표에도 득표가 누락되지 않는다.

### API

- [x] `POST /api/polls/[id]/vote` 가 `{ optionId }` 를 받아 성공 시 `200` 과 `{ ok: true }` 를 돌려준다.
- [x] 없는 투표·형식이 잘못된 투표 id → `404` 와 `{ error }`.
- [x] `optionId` 누락, 형식 오류(uuid 아님), 그 투표에 속하지 않은 선택지, 없는 선택지, 잘못된 JSON → `400` 과 `{ error }`, 득표수 변화 없음.
- [x] 오류 문구는 모두 한국어이다.

### 화면

- [x] `/polls/[id]` 에 질문과 선택지를 라디오 버튼으로 보여주는 투표 폼(클라이언트 컴포넌트)과 제출 버튼을 추가한다. 하나만 선택할 수 있다.
- [x] 선택하지 않고 제출하면 요청을 보내지 않고 안내 문구를 보여준다.
- [x] 제출 시 `POST /api/polls/[id]/vote` 를 `fetch` 로 호출하고, 성공하면 `/polls/[id]/results` 로 이동한다. 실패하면 응답의 `error` 문구를 그대로 보여준다.
- [x] 03 이 완료되기 전에는 이동한 결과 화면이 404 일 수 있다 (의도된 순서; 득표 반영은 `GET /api/polls/[id]` 로 확인).

### 테스트 (Route Handler 경계, polls 데이터 접근 모듈은 메모리 가짜)

- [x] 정상 투표 → `200`, `{ ok: true }`, 이후 `GET /api/polls/[id]` 에서 고른 선택지만 1 증가하고 다른 선택지는 그대로다.
- [x] 같은 선택지에 두 번 투표하면 2 가 된다 (중복 방지 없음, ADR-0001).
- [x] `optionId` 누락·형식 오류·다른 투표의 선택지·없는 선택지 → `400` + `{ error }`, 모든 득표수 변화 없음.
- [x] 없는 투표·형식이 잘못된 투표 id → `404` + `{ error }`.
- [x] 01 의 테스트를 포함해 `npm run test` 가 모두 통과한다.

### 수동 확인 (`npm run dev`)

- [x] 투표 화면에서 선택 후 제출하면 결과 화면 주소로 이동하고, `GET /api/polls/[id]` 에서 득표수가 1 오른 것이 보인다.
- [x] 선택 없이 제출하면 화면에서 막힌다.
