# 03: 결과 보기

**What to build:** 투표자(Voter)가 `/polls/[id]/results` 에서 투표(Poll)의 질문과 선택지(Option)별 득표수를 숫자 리스트로 본다. 아직 아무도 투표하지 않았으면 모든 선택지가 0 으로 보인다. 결과는 투표하지 않아도 언제든 볼 수 있고, 항상 최신 득표수를 보여준다. 투표 화면에는 "결과 보기" 링크가, 결과 화면에는 목록과 투표 화면으로 돌아가는 링크가 생긴다. 총 투표수·퍼센트·그래프는 부록 단계에서 다룬다.

스펙: `.scratch/voting-app-mvp/spec.md` (User Stories 29, 33–37)

**Blocked by:** 01 (투표 만들기)

**Status:** ready-for-agent

### 화면

- [x] `/polls/[id]/results` 는 서버 컴포넌트가 polls 데이터 접근 모듈(01 의 투표 상세 조회)로 직접 읽어, 질문과 선택지별 득표수(`vote_count`)를 숫자 리스트로 보여준다. 총 투표수와 퍼센트는 표시하지 않는다.
- [x] 투표가 0 건이면 모든 선택지가 0 으로 오류 없이 표시된다.
- [x] 요청마다 최신 득표수를 보여준다 (캐시된 오래된 값을 보여주지 않음). 투표 후 이동했을 때 방금 한 투표가 반영되어 있다.
- [x] 없는 투표·형식이 잘못된 id 는 `notFound()` 로 404 화면이다.
- [x] 결과 화면에 목록(`/`)으로 가는 링크와 그 투표의 투표 화면(`/polls/[id]`)으로 가는 링크가 있다.
- [x] `/polls/[id]` 투표 화면에 "결과 보기" 링크를 추가한다 (투표하지 않아도 결과를 볼 수 있다).
- [x] 모든 화면 문구는 한국어이고, 공통 Header 가 보인다.

### 테스트

- [x] 새 API 는 없다. 결과 화면이 쓰는 데이터 형식은 01 의 `GET /api/polls/[id]` 테스트(득표수 포함 형식, 0 건, 404)로 보장된다. 필요하면 득표수가 여러 선택지에 걸쳐 있는 조회 케이스를 Route Handler 경계 테스트에 추가한다.
- [x] 기존 테스트를 포함해 `npm run test` 가 모두 통과한다.

### 수동 확인 (`npm run dev`)

- [x] 새로 만든 투표의 결과 화면에서 모든 선택지가 0 으로 보인다.
- [x] 투표 화면에서 투표하면 결과 화면으로 이동하고, 고른 선택지의 득표수가 1 올라 있다.
- [x] 투표 화면의 "결과 보기" 링크, 결과 화면의 목록·투표 화면 링크가 동작한다.
- [x] 없는 id 의 결과 주소는 404 화면이다.
