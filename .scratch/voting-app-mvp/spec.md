# Spec: 투표 앱 MVP (기본 앱)

Status: ready-for-agent

## Problem Statement

동아리 회장의 요청: "우리 동아리에서 쓸 투표 앱을 하나 만들어주면 좋겠어요. 질문 하나 올리면 사람들이 선택지 중 하나를 골라서 투표하고, 결과를 볼 수 있으면 돼요."

지금은 질문을 올리고, 사람들이 선택지 중 하나를 고르고, 그 결과를 함께 확인할 수 있는 간단한 도구가 없다. 또한 이 앱은 학교 과제 제출물이므로 모든 화면에서 제작자가 누구인지 드러나야 한다.

## Solution

로그인 없이 누구나 쓸 수 있는 웹 투표 앱을 만든다.

- 누구나 질문 하나와 선택지 2~5개로 투표(Poll)를 만든다.
- 투표자(Voter)는 투표 목록에서 투표를 골라, 선택지(Option) 하나를 선택해 투표 행위(Vote)를 한다.
- 투표 후에는 결과 화면으로 이동해 선택지별 득표수를 숫자로 확인한다. 결과는 투표하지 않아도 언제든 볼 수 있다.
- 모든 화면 상단에 `투표 앱 · 제작자: 임정민` 이 표시된다.

## User Stories

### 공통 / 제작자 표시

1. As a 과제 채점자, I want 모든 페이지 상단에 "투표 앱 · 제작자: 임정민"이 보이기를, so that 어느 화면 캡처를 보더라도 제작자를 확인할 수 있다
2. As a 투표자, I want 어느 페이지에서든 상단 Header의 "투표 앱"을 눌러 목록으로 돌아가기를, so that 길을 잃지 않는다
3. As a 투표자, I want 모든 화면 문구가 한국어이기를, so that 동아리 구성원 누구나 쉽게 이해할 수 있다

### 투표 목록 (`/`)

4. As a 투표자, I want 전체 투표 목록을 한 화면에서 보기를, so that 참여할 투표를 고를 수 있다
5. As a 투표자, I want 목록이 최신순으로 정렬되기를, so that 새로 올라온 투표를 먼저 볼 수 있다
6. As a 투표자, I want 목록의 각 항목에 투표의 질문만 간결하게 보이기를, so that 한눈에 훑어볼 수 있다
7. As a 투표자, I want 목록의 질문을 누르면 그 투표의 투표 화면으로 이동하기를, so that 바로 투표할 수 있다
8. As a 투표를 만드는 사람, I want 목록 상단에 항상 "투표 만들기" 링크가 있기를, so that 언제든 새 투표를 만들 수 있다
9. As a 투표자, I want 투표가 하나도 없을 때 "아직 투표가 없습니다" 안내와 "투표 만들기" 링크를 보기를, so that 빈 화면에서 무엇을 해야 할지 알 수 있다

### 투표 만들기 (`/new`)

10. As a 투표를 만드는 사람, I want 질문 하나를 입력하기를, so that 구성원에게 무엇을 묻는지 정할 수 있다
11. As a 투표를 만드는 사람, I want 처음에 선택지 입력 칸 2개가 준비되어 있기를, so that 최소 개수를 바로 채울 수 있다
12. As a 투표를 만드는 사람, I want "선택지 추가" 버튼으로 선택지 칸을 최대 5개까지 늘리기를, so that 필요한 만큼 선택지를 줄 수 있다
13. As a 투표를 만드는 사람, I want 선택지가 5개가 되면 더 추가할 수 없기를, so that 허용 범위를 넘지 않는다
14. As a 투표를 만드는 사람, I want 3번째 선택지부터 삭제 버튼이 있기를, so that 잘못 추가한 칸을 지울 수 있다
15. As a 투표를 만드는 사람, I want 1·2번째 선택지는 삭제할 수 없기를, so that 선택지가 2개 미만이 되지 않는다
16. As a 투표를 만드는 사람, I want 질문이나 선택지가 공백뿐이면 제출이 거부되고 안내를 보기를, so that 빈 투표가 만들어지지 않는다
17. As a 투표를 만드는 사람, I want 같은 투표 안에 이름이 같은 선택지가 있으면 거부되기를, so that 투표자가 헷갈리지 않는다
18. As a 투표를 만드는 사람, I want 질문이 200자, 선택지가 100자를 넘으면 거부되기를, so that 화면이 깨지지 않는다
19. As a 투표를 만드는 사람, I want 입력 앞뒤의 공백이 자동으로 정리되기를, so that 실수로 넣은 공백이 저장되지 않는다
20. As a 투표를 만드는 사람, I want 입력 오류가 있으면 화면에서 먼저 안내받기를, so that 제출 전에 고칠 수 있다
21. As a 투표를 만드는 사람, I want 화면 검증을 우회하더라도 서버가 같은 규칙으로 거부하기를, so that 잘못된 투표가 절대 저장되지 않는다
22. As a 투표를 만드는 사람, I want 서버가 거부했을 때 그 한국어 안내 문구가 화면에 그대로 보이기를, so that 무엇이 잘못됐는지 알 수 있다
23. As a 투표를 만드는 사람, I want 투표를 만든 직후 그 투표의 투표 화면으로 이동하기를, so that 바로 확인하고 주소를 공유할 수 있다

### 투표하기 (`/polls/[id]`)

24. As a 투표자, I want 투표 화면에서 질문과 선택지를 보기를, so that 무엇에 투표하는지 알 수 있다
25. As a 투표자, I want 라디오 버튼으로 선택지 하나만 고르기를, so that 단일 선택 규칙이 분명하다
26. As a 투표자, I want 선택지를 고르지 않고 제출하면 화면에서 막히고 안내를 보기를, so that 빈 투표를 실수로 보내지 않는다
27. As a 투표자, I want 제출하면 내가 고른 선택지의 득표수가 1 오르기를, so that 내 투표가 반영된다
28. As a 투표자, I want 제출 후 결과 화면으로 이동하기를, so that 내 투표가 반영된 결과를 바로 본다
29. As a 투표자, I want 투표 화면에 "결과 보기" 링크가 있기를, so that 투표하지 않고도 결과를 확인할 수 있다
30. As a 투표자, I want 동시에 여러 사람이 투표해도 득표수가 누락되지 않기를, so that 결과를 믿을 수 있다
31. As a 투표자, I want 존재하지 않거나 형식이 잘못된 투표 주소로 들어가면 404 화면을 보기를, so that 잘못된 링크임을 알 수 있다
32. As a 투표자, I want 다른 투표의 선택지나 존재하지 않는 선택지로 투표 요청이 오면 거부되기를, so that 득표수가 엉뚱하게 바뀌지 않는다

### 결과 보기 (`/polls/[id]/results`)

33. As a 투표자, I want 결과 화면에서 질문과 선택지별 득표수를 숫자 리스트로 보기를, so that 어떤 선택지가 많이 선택됐는지 알 수 있다
34. As a 투표자, I want 결과 화면이 항상 최신 득표수를 보여주기를, so that 방금 한 투표가 반영된 것을 확인할 수 있다
35. As a 투표자, I want 아직 아무도 투표하지 않은 투표의 결과도 모든 선택지가 0으로 정상 표시되기를, so that 오류 없이 현재 상태를 볼 수 있다
36. As a 투표자, I want 존재하지 않는 투표의 결과 주소로 들어가면 404 화면을 보기를, so that 잘못된 링크임을 알 수 있다
37. As a 투표자, I want 결과 화면에서 목록이나 투표 화면으로 돌아갈 수 있기를, so that 다른 투표에도 참여할 수 있다

### API 사용자 (화면의 폼, 또는 직접 호출)

38. As an API 사용자, I want `POST /api/polls` 에 `{ question, options }` 를 보내 투표를 만들고 `201` 과 `{ id }` 를 받기를, so that 만든 투표로 이동할 수 있다
39. As an API 사용자, I want `GET /api/polls/[id]` 로 `{ id, question, created_at, options: [{ id, label, vote_count }] }` 를 받기를, so that 투표 상세와 득표수를 알 수 있다
40. As an API 사용자, I want `POST /api/polls/[id]/vote` 에 `{ optionId }` 를 보내 `200` 과 `{ ok: true }` 를 받기를, so that 투표가 반영됐음을 안다
41. As an API 사용자, I want 모든 오류가 `{ error: "<한국어 안내 문구>" }` 형식으로 오기를, so that 화면이 한 가지 방식으로 오류를 보여줄 수 있다
42. As an API 사용자, I want 없는 투표나 형식이 잘못된 id에는 `404`, 잘못된 입력에는 `400` 을 받기를, so that 오류 종류를 구분할 수 있다

## Implementation Decisions

### 기술 스택 (수업자료 1장)

- Next.js 16 App Router + Route Handlers + TypeScript, 스타일은 기존 Tailwind 로 간단하고 깔끔하게.
- Neon Postgres, `@neondatabase/serverless` 드라이버, ORM 없이 raw SQL. 연결 문자열은 환경변수 `DATABASE_URL` 로만 읽는다.
- 이 프로젝트의 Next.js 는 학습 데이터와 다를 수 있으므로, 구현 전 설치된 Next.js 문서를 확인한다 (AGENTS.md).

### 스키마 (수업자료 2장 그대로)

- `polls`: `id` (uuid, 기본키, `gen_random_uuid()`), `question` (text, not null), `created_at` (timestamptz, not null, 기본값 `now()`).
- `options`: `id` (uuid, 기본키, `gen_random_uuid()`), `poll_id` (uuid, not null, `polls(id)` 참조, `on delete cascade`), `label` (text, not null), `vote_count` (integer, not null, 기본값 0).
- 추가 테이블(`votes` 등)이나 컬럼은 만들지 않는다.
- 스키마 SQL 은 저장소에 파일로 남기고, 수업자료대로 Neon SQL Editor 에서 사람이 직접 실행한다. 앱이 자동으로 마이그레이션하지 않는다.

### 모듈

- **DB 연결 모듈**: `DATABASE_URL` 로 Neon `sql` 클라이언트를 만든다. 그 외 로직 없음.
- **polls 데이터 접근 모듈**: 투표 관련 SQL 을 모두 여기에 모은다. 서버 컴포넌트와 Route Handler 가 이 모듈만 통해 DB 에 접근한다. 인터페이스(개념 수준):
  - 투표 목록 조회: 최신순(`created_at desc`), 목록에 필요한 `id`, `question`.
  - 투표 상세 조회: id 로 투표와 선택지(득표수 포함)를 가져오고, 없으면 "없음"을 돌려준다.
  - 투표 생성: 검증된 질문과 선택지 목록을 받아 투표와 선택지를 저장하고 새 투표 id 를 돌려준다.
  - 득표 1 증가: 투표 id 와 선택지 id 를 받아, **그 투표에 속한 선택지일 때만** `vote_count = vote_count + 1` 로 증가시키고 성공 여부를 돌려준다. 원자적 증가이므로 동시 투표에도 안전하다.
- **투표 입력 검증 모듈** (순수 함수, 서버·화면 공용): 질문과 선택지 목록을 받아, 앞뒤 공백을 제거한 정리된 값 또는 한국어 오류 문구를 돌려준다. 규칙:
  - 질문: 공백 제거 후 비어 있으면 거부, 200자 초과 거부.
  - 선택지: 2개 미만 또는 5개 초과 거부, 공백 제거 후 빈 선택지 거부, 100자 초과 거부, 같은 투표 안의 중복 이름 거부.
  - `/new` 폼과 `POST /api/polls` 가 같은 함수를 써서 규칙이 어긋나지 않게 한다. 서버 검증은 필수이다.
- **id 형식 확인**: 투표 id·선택지 id 가 uuid 형식이 아니면 DB 조회 없이 "없음"(페이지는 404, API 는 404/400)으로 처리한다.

### 읽기 / 쓰기 경로

- **읽기**: 목록, 투표 화면, 결과 화면은 서버 컴포넌트가 polls 데이터 접근 모듈로 DB 를 직접 읽는다. 서버 컴포넌트에서 자기 Route Handler 를 호출하지 않는다 (Next.js 문서 권고).
- **쓰기**: 투표 만들기와 투표 제출은 클라이언트 컴포넌트 폼이 API 를 `fetch` 로 호출한다.
- 결과 화면과 투표 화면은 요청마다 최신 데이터를 보여줘야 한다 (캐시된 오래된 득표수를 보여주지 않는다).

### API 계약 (수업자료 2장의 3개)

- `POST /api/polls`
  - 요청: `{ question: string, options: string[] }`
  - 성공: `201`, `{ id }`
  - 검증 실패·잘못된 JSON: `400`, `{ error }`
- `GET /api/polls/[id]`
  - 성공: `200`, `{ id, question, created_at, options: [{ id, label, vote_count }] }`
  - 없는 투표·형식이 잘못된 id: `404`, `{ error }`
- `POST /api/polls/[id]/vote`
  - 요청: `{ optionId: string }`
  - 성공: `200`, `{ ok: true }`
  - 없는 투표·형식이 잘못된 투표 id: `404`, `{ error }`
  - `optionId` 누락, 형식 오류, 그 투표에 속하지 않은 선택지: `400`, `{ error }`, 득표수 변경 없음
- 모든 오류 응답은 `{ error: "<한국어 안내 문구>" }` 형식이며, 화면은 이 문구를 그대로 보여준다.
- 응답 필드 이름은 DB 컬럼 이름(`vote_count`, `created_at`)을 그대로 쓴다.

### 화면

- **공통 Header** (루트 레이아웃): 모든 페이지 상단에 `투표 앱 · 제작자: 임정민`. "투표 앱"은 목록(`/`) 링크.
- **`/`**: 질문만 최신순으로 나열, 각 항목은 투표 화면 링크. 상단에 항상 "투표 만들기" 링크. 투표가 없으면 "아직 투표가 없습니다" 와 "투표 만들기" 링크.
- **`/new`**: 질문 입력 1개 + 선택지 입력 2개로 시작. "선택지 추가"로 최대 5개, 3번째부터 삭제 버튼. 화면 검증 후 API 호출, 성공 시 `/polls/[id]` 로 이동, 실패 시 서버 오류 문구 표시.
- **`/polls/[id]`**: 질문과 선택지를 라디오 버튼으로 표시, 제출 버튼. 미선택 제출은 화면에서 막고 안내. 성공 시 `/polls/[id]/results` 로 이동. "결과 보기" 링크 제공. 없는 투표면 `notFound()`.
- **`/polls/[id]/results`**: 질문과 선택지별 득표수를 숫자 리스트로 표시 (총 투표수·퍼센트 없음). 없는 투표면 `notFound()`.

### 인증 / 중복 투표 (ADR-0001)

- 투표자 로그인, 운영자 인증, 중복 투표 방지를 구현하지 않는다. 누구나 투표를 만들고 투표할 수 있으며, 같은 사람이 여러 번 투표할 수 있다.

## Testing Decisions

- **좋은 테스트의 기준**: 외부에서 관찰 가능한 동작(HTTP 상태 코드와 JSON 본문, 득표수 변화)만 검증한다. SQL 문자열, 내부 함수 호출 순서 같은 구현 세부사항은 검증하지 않는다.
- **테스트 도구**: Vitest. 테스트 파일은 `*.test.ts` 형식, 실행은 `npm run test`.
- **테스트 경계(seam)는 하나: Route Handler 3개.** 테스트는 각 handler 에 실제 `Request` 를 넘기고 응답을 검증한다.
- **polls 데이터 접근 모듈은 메모리 기반 가짜로 대체**한다. 가짜는 실제 모듈과 같은 인터페이스를 가지며, 투표 생성·조회·득표 증가를 메모리에서 수행한다. 테스트용 Neon 브랜치는 만들지 않는다.
- **테스트할 것**:
  - `POST /api/polls`: 정상 생성(201, `{ id }`, 이후 GET 으로 조회 가능, 공백 정리된 값 저장, 득표수 0), 빈/공백 질문, 선택지 1개·6개, 빈 선택지, 중복 선택지, 질문 201자·선택지 101자, 경계값(선택지 2개·5개, 질문 200자·선택지 100자 허용), 잘못된 JSON → 모두 400 과 `{ error }`.
  - `GET /api/polls/[id]`: 정상 조회 형식, 없는 id·형식이 잘못된 id → 404 와 `{ error }`.
  - `POST /api/polls/[id]/vote`: 정상 투표 시 200 `{ ok: true }` 와 해당 선택지만 1 증가, `optionId` 누락·형식 오류·다른 투표의 선택지·없는 선택지 → 400 이고 득표수 변화 없음, 없는 투표 → 404.
- **자동 테스트하지 않는 것**:
  - polls 데이터 접근 모듈 안의 실제 SQL 과 DB 연결 — `npm run dev` 와 Neon 에서 직접 확인.
  - UI(선택지 추가·삭제, 미선택 제출 차단, 화면 이동, Header 표시) — `npm run dev` 로 직접 확인. 컴포넌트 테스트, Testing Library, jsdom 은 추가하지 않는다. 화면 검증은 서버와 같은 검증 함수를 쓰므로 규칙은 API 테스트로 함께 보장된다.
- **기존 테스트(prior art)**: 저장소에 아직 테스트가 없다. 이 스펙의 첫 티켓에서 Vitest 설정과 `npm run test` 스크립트를 추가한다.

## Out of Scope

- **부록(과제 요구사항 1·2)으로 미룸**: 투표 마감 시간(`closes_at`), 결과 그래프, 결과의 총 투표수·퍼센트 표시. 기본 앱 완성 후 부록 자료 기준으로 별도 `/grill-with-docs` 부터 진행한다.
- **수업자료 7장 예상 산출물(B)에만 있는 기능**: Admin 로그인·세션·`proxy.ts` 가드, 쿠키 기반 중복 투표 차단, 복수 선택(Choice Mode), 결과 공개 조건(투표해야 결과 보기), 결과 폴링(실시간 갱신), 투표 삭제, `votes` 테이블.
- 투표·선택지 수정 기능.
- 컴포넌트 테스트, E2E 테스트(Playwright), 테스트용 DB.
- 배포(Vercel)는 수업자료 부록 가이드로 별도 진행.
